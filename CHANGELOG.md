# Changelog

All notable changes to this project are documented here.
Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
versioning follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.1] - 2026-07-30

First public release of the 2.x line.

### Added

- Back-office notice explaining the `Ã©` mojibake and the one-line `.htaccess`
  fix (`AddCharset UTF-8 .txt`). Apache serves `.txt` as `text/plain` with no
  charset, so browsers fall back to Latin-1 and mangle every accent even though
  the file is valid UTF-8. The notice only appears when the generated file
  actually contains non-ASCII bytes, so English-only shops never see it.
- `config.xml` shipped with the module, so upgrade scripts run on first load.
- Installation step and a dedicated README section covering the same charset
  issue, including why the module does not ship a UTF-8 BOM to paper over it.

### Fixed

- The generation timestamp toggle defaulted to off on shops upgrading straight
  from 1.x, because the configuration key did not exist yet when the form was
  first rendered. The upgrade script now seeds it.

## [2.0.0] - 2026-07-30

Entries carry real descriptions instead of generic type labels.

Until now every line ended with `: CMS page` or `: Product`, which tells the
reader this file is written for exactly nothing. Entries now carry the
resource's own meta description, in each shop language.

Still a single PHP file. No namespace, no autoloader, no `src/` tree: shared
hosts run antivirus scanners that quarantine dynamic class loaders by renaming
them, which turns the module's `require_once` into a fatal error and takes the
back office down with it.

### Added

- **Meta descriptions as entry descriptions**, read from `cms_lang`,
  `category_lang` and `product_lang`. Falls back to the category description or
  the product short description, clamped on a word boundary, then to the type
  label.
- **Status panel** in the back office: file URL, last generation timestamp,
  duration, size, entry counts per language, and last error.
- **Generate now** button, separate from saving settings.
- **Optional cron endpoint** at `/module/ps_llms_generator/regenerate`, protected
  by a rotatable token compared with `hash_equals()`. Prefers an `X-Llms-Token`
  header so the secret stays out of access logs; a `?token=` query string is
  accepted for cron runners that cannot send headers. Generation stays manual
  until a schedule is wired.
- **Generation timestamp** written in the file, toggleable, so a stale file is
  obvious at a glance.
- `upgrade/upgrade-2.0.0.php`, preserving every 1.x setting.

### Changed

- **Three flat SQL queries**, one per entity type, covering every language at
  once. URLs are built from `id + link_rewrite`, which lets `Link::get*Link()`
  skip object hydration entirely, verified against PrestaShop 8.2.4. The 1.x
  loop instantiated one `CMS`, `Category` or `Product` object per row *per
  language*.
- **Atomic write**: the file is built in a temporary under
  `var/cache/<env>/modules/ps_llms_generator/`, then `rename()`d into place. A
  crawler hitting the URL mid-generation can no longer read a half-written file,
  and a crashed run leaves nothing publicly readable.
- Emoji, pictographs and flags are stripped from titles. Trademark, registered
  and copyright signs are kept, they belong in product names.
- Em dashes and en dashes are normalised to a plain hyphen.
- HTML entities are decoded and block-level tags become spaces, so sentences no
  longer glue together.
- Section headings use a plain hyphen separator.
- `uninstall()` removes every configuration key and deletes the generated file.

### Fixed

- **Check all / Uncheck all did nothing.** 1.x interpolated PHP into a
  double-quoted string and emitted
  `querySelectorAll("input[name="PSLLMS_CMS_ENABLED[]"]")`, an unparseable
  selector that silently broke the whole inline script. The JavaScript is now a
  nowdoc.
- Markdown link grammar is protected: brackets, parentheses and pipes are
  neutralised in labels, parentheses are percent-encoded in URLs, and an empty
  label falls back to the URL.
- Malformed UTF-8 no longer blanks a whole title: a `preg_replace()` returning
  `null` is caught and the input kept.

### Removed

- The UTF-8 BOM. It renders as a stray glyph in front of the H1 in most Markdown
  readers, which is the wrong trade for a file meant to be parsed by machines.
  Use the `.htaccess` charset directive instead.
- Prices and stock status are deliberately not written. A file regenerated by
  hand would advertise stale figures, which is not acceptable for a shop selling
  regulated goods.
